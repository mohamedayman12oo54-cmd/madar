## 4. Kashier facts used for planning (to be verified; not decided)

From public docs reviewed 2026-10-15: no managed subscriptions, so the merchant owns the schedule and charges
the saved token (`POST /v3/orders`, `interactionSource=CONTAUTH`); setup via `POST /v3/payment/sessions` with an
`agreement` object (`type=RECURRING|UNSCHEDULED`, `paymentFrequency` example `MONTHLY`,
`minimumDaysBetweenPayments`, `expiryDate`, `numberOfPayments`, `maximumAmountPerPayment`, `amountVariability`);
webhook header `x-kashier-signature`, HMAC-SHA256 hex over sorted `data.signatureKeys` with URL-encoded values;
branch on `data.status`, not `event`; ack 200/409 within 30 s; up to 10 retries; payload ids `merchantOrderId`,
`kashierOrderId`, `orderReference`, `transactionId`; per-mode keys; separate live webhook required. **None of
these resolves BILL-EXT-01.**
